## 1. 개요

### 1.1 한 줄 정의
카메라로 손 제스처를 인식해 드론을 조종하는 방식을 **실기체 없이 3D 시뮬레이션으로 훈련하고, 훈련 기록을 교관이 사후검토할 수 있는 웹 기반 교육훈련 도구**.

### 1.2 배경
- **정책 방향:** 육군은 Army TIGER+ 정책을 현실화하고 유무인 복합 전투체계를 구현하기 위해 Physical AI 도입을 추진 중이다. 2026년 10월 14일 양평훈련장 'Army TIGER+ 미래전 통합 전투수행훈련'에서 2040년 미래 육군 청사진, 6대 개혁 중점, 국방로봇·피지컬 AI 중심의 유무인복합부대 전환 방향이 공개됐다 [R1].
- **현장 현실:** Army TIGER+ 시범부대에서 많은 드론을 운용하고 있지만, 여전히 전용 물리 조종기(조이스틱, GCS)로 조작하고 있다.
- **물리 조종기의 한계**

| 구분 | 문제 |
|---|---|
| 비용 | 디스플레이 내장 프로급 조종기나 군용 GCS는 기체 가격과 비슷할 만큼 비싸다. 낙하·침수로 파손되면 수리비가 크고, 기종을 바꾸면 호환이 안 돼 새로 사야 한다. |
| 휴대성 | 부피와 무게가 크고, 하드케이스와 스트랩이 별도로 필요하다. |
| 준비 절차 | 안테나 전개, 바인딩, 캘리브레이션 등 비행 전 준비가 복잡하다. |
| 단일 장애점 | 조종기 배터리가 방전되거나 고장·파손되면 비행 중인 기체와 대기 중인 기체 모두 제어 수단이 사라진다. |
| 종속성 | 특정 제조사의 특정 기종(세대) 전용인 경우가 많다. |
| 관리 부담 | 조종기 배터리 충전·수명 관리와 정기 펌웨어 업데이트가 필요하고, 이를 소홀히 하면 연결 오류가 생긴다. |

### 1.3 제품 목표
1. 제스처 기반 드론 조종이 **기술적으로 가능하고 직관적**이라는 점을 시연으로 입증한다.
2. 실기체 없이 **반복 훈련**하고, **조작 성공률과 잘못된 습관 데이터**를 축적한다.
3. Army TIGER+ 및 유무인 복합 전투체계와의 연계 방향을 설명하는 **교육·홍보 자료** 역할을 한다.

### 1.4 사용자

| 사용자 | 목적 | 주요 화면 |
|---|---|---|
| 훈련자 (드론 운용부대 인원) | 제스처 조종 연습, 내 기록 확인 | 환경설정, 시뮬레이션, 사후검토(개인) |
| 교관 | 다수 훈련자의 기록 비교, 사후검토 진행 | 사후검토(교관) |
| 보고·발표 청중 (지휘관, 평가자) | 체계 필요성과 가능성 이해 | 체계 소개, 시뮬레이션 시연 |

## 2. 범위

### 2.1 MVP 핵심 기능 (3개)

| # | 기능 | 설명 |
|---|---|---|
| F1 | **손 제스처 인식 + 3D 드론 제어** | 왼쪽 화면은 카메라 손 인식, 오른쪽 화면은 3D 드론. 수신호 7종에 실시간 반응 |
| F2 | **훈련 미션 및 채점** | 단계별 과제를 내고 성공 여부, 소요 시간, 실수를 기록해 공유 저장소에 쌓음 |
| F3 | **사후검토 화면** | 개인 성공률 추이와 잘못된 습관 분석, 교관용 전체 비교, CSV 내보내기 |

### 2.2 콘텐츠 화면 (MVP에 포함, 내용 위주)
체계 소개 및 배경, 환경설정 및 조작방법(매뉴얼 다운로드 포함), 관련 정보(학습), 제작자 소개.

### 2.3 제외 범위
- 로그인, 회원가입, 결제
- 실제 드론 기체 연동 (MAVLink, DJI SDK 등)
- 전진·후진, 회전(yaw) 제스처
- 부대 내부망(오프라인) 패키지
- 다국어 지원

## 3. 화면 구성 (정보 구조)

상단 고정 내비게이션에서 6개 화면을 순서대로 오간다.

```
① 체계 소개 및 배경 → ② 환경설정 및 조작방법 → ③ 조작 시뮬레이션
→ ④ 사후검토 → ⑤ 관련 정보(학습) → ⑥ 제작자 소개
```

공통 요소:
- **헤더:** Army TIGER 엠블럼(제공 이미지), 체계명, 내비게이션
- **푸터:** "연구·교육용 시제품" 표기, 문의 메일
- **반응형:** PC 기준으로 설계하고, 스마트폰에서는 카메라와 시뮬레이터를 위아래로 배치

### ① 체계 소개 및 배경
- **Army TIGER+ 와 유무인 복합 전투체계** (출처: 육군 보도자료 [R1])

| 정책 요소 | 화면에 담을 내용 |

| 추진 배경 | AI·로봇 기술 발전, 병역자원 감소, 다양한 안보위협 → 병력 중심 전투수행체계를 AI·무인체계 기반으로 전환 |
| 2040 청사진 | Army TIGER+ 중심의 2040년 미래 육군 청사진과 6대 개혁 중점 |
| 정부 3대 메가프로젝트 연계 | 반도체, 로봇·피지컬 AI, AI데이터센터를 국방분야에서 연결·통합·확장. 육군은 로봇·피지컬 AI의 최대 수요처이자 동적 데이터의 최대 공급처 |
| 현장 기반의 변혁(TiC) | 시범부대를 14개 유형으로 확대해 실증. 판교 AX 거점과 양평·무건리 훈련장을 연계한 실증환경 구축 |
| 무인체계부대 | 통합무인전투대('26.1.28. 출범, 드론봇중대 기반), 유무인복합분대('26.7.29. 출범) |
| 디지털 백본 | 드론·로봇 등 첨단전력을 하나의 네트워크로 연결, 소부대부터 대부대까지 단계적 확대 |
| 인적 기반 | '50만 드론 전사 양성' 정책, 실증전담부대 확대, 부대별 혁신랩 운용 |
| 시현된 전투 모습 | 드론·대드론전, 통합무인전투, 유무인복합전투 |

- **본 체계와의 관계**

| 정책 요소 | 본 체계의 기여 |
|---|---|
| 50만 드론 전사 양성 | 실기체·고가 조종기 없이 누구나 PC·폰으로 반복 훈련할 수 있는 저비용 교육훈련 수단 |
| 현장 기반의 변혁(TiC) | 시범부대·혁신랩에서 바로 실증할 수 있는 소프트웨어 시제품. 실증 결과로 성능과 소요를 구체화하는 진화적 발전 방식에 부합 |
| 피지컬 AI 데이터 선순환 | 훈련 중 생성되는 제스처·조작 데이터를 축적해 향후 학습 기반 인식 고도화에 활용 |
| 유무인복합분대·통합무인전투대 | 전투원이 손 동작만으로 무인체계를 통제하는 HMI(인간-기계 인터페이스) 개념 검증 |
| 디지털 백본 | 기종 독립적인 소프트웨어 통제 계층으로, 다양한 드론을 하나의 인터페이스로 통제하는 방향 제시 |
- **"언제까지 조종기로 조종할 것인가?" 비교 분석**

| 비교 항목 | 전용 물리 조종기 | 제스처 기반 조종 |
|---|---|---|
| 장비 비용 | 고가, 파손 시 수리·재구매 | 기존 스마트폰·PC 카메라 활용 |
| 휴대성 | 부피·무게 큼, 케이스 필요 | 별도 장비 없음 |
| 준비 시간 | 안테나 전개, 바인딩, 캘리브레이션 | 카메라 권한 허용 후 즉시 사용 |
| 장애 대응 | 조종기 고장 시 제어 수단 상실 | 카메라가 있는 다른 단말로 즉시 대체 |
| 호환성 | 제조사·기종에 종속 | 소프트웨어 계층에서 기종 독립 설계 가능 |
| 유지관리 | 조종기 배터리·펌웨어 별도 관리 | 앱·웹 업데이트로 일원화 |
| 정밀 제어·신호 안정성 | **우수** | 조명·가림 등 환경 영향, 보완 필요 |

  마지막 행처럼 한계도 솔직하게 함께 제시해 신뢰도를 높이고, 과제를 "조종기를 대체"가 아니라 "조종기 의존도를 낮추는 보조·예비 통제 수단"으로 시작해 단계적으로 확대한다는 메시지로 마무리한다.

### ② 환경설정 및 조작방법

**환경 점검 (자동 체크리스트)**

| 점검 항목 | 확인 방법 | 표시 |
|---|---|---|
| 브라우저 | 크롬·엣지 등 지원 브라우저 여부 | 정상 / 비권장 |
| 카메라 장치 | 연결된 카메라 존재 여부 | 감지됨 / 없음 |
| 카메라 권한 | 브라우저 권한 상태 | 허용 / 차단 / 미요청 |
| 카메라 동작 | 영상 스트림 수신 여부 | 켜짐 / 꺼짐 |
| AI 모델 | 손 인식 모델 로딩 여부 | 준비 완료 / 로딩 중 / 실패 |

- 권한이 차단된 경우 크롬, 엣지, 기타 브라우저(사용자가 말한 "aside" 포함)별로 권한 허용 방법을 안내한다.
- HTTPS 환경에서만 카메라가 동작한다는 점, 다른 앱(화상회의 등)이 카메라를 쓰고 있으면 실패할 수 있다는 점을 안내한다.

**수신호 조작법:** 제스처마다 카드 1장 (손 모양 그림, 동작 방법, 드론 반응, 흔한 실수). 상세 정의는 4장 참조.

**매뉴얼 다운로드:** 수신호 카드 7종, 환경 점검 절차, 안전 규칙을 담은 1~2쪽 PDF.

### ③ 조작 시뮬레이션

```
┌──────────── 상태 바: 카메라 ● 권한 ● AI모델 ● 드론전원 ● 현재 미션 ────────────┐
├───────────── 왼쪽: 카메라 ─────────────┬──────────── 오른쪽: 3D 드론 ────────────┤
│ 거울 반전 영상 + 손 관절 21점 오버레이  │ 3D 드론, 지면 격자, 목표 지점/고도 링    │
│ 인식된 제스처 이름 + 신뢰도 게이지      │ 고도·위치·전원·배터리(가상) 계기         │
│ 유지 시간 진행 바 (0.5초 / 1초)         │ 미션 지시문 + 남은 시간 + 진행 단계       │
├────────────────────────────────────────┴──────────────────────────────────────────┤
│ 하단: 훈련자(계급+이름) · 미션 선택 · 시작/중단 · 실시간 명령 로그                    │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

- **자유비행 모드:** 채점 없이 연습한다.
- **훈련 미션 모드:** 채점하고 기록을 저장한다 (5장).
- 훈련 시작 전 **계급과 이름(또는 훈련 번호)**을 입력한다. 군번 등 식별 정보는 받지 않는다.

### ④ 드론 교육훈련 사후검토

| 구분 | 내용 |
|---|---|
| 개인 화면 | 회차별 성공률·점수 추이, 미션별 성공/실패, 평균 소요 시간, **잘못된 습관 Top 3** (예: "엄지 아래를 손바닥 아래로 혼동 7회"), 회차 상세 로그 |
| 교관 화면 | 훈련자 전체 목록과 최근 점수, 미션별 평균 성공률, 실수 유형 분포, 훈련자 비교, **CSV 내보내기** |
| 자동 코멘트 | 실수 유형별 교정 문구 (예: 공중 전원차단 시도 → "착륙 후 전원 차단 절차 숙지") |

### ⑤ 관련 정보 (학습 페이지)
1. **모션 인식 AI 이론**
   - 컴퓨터 비전 기초: 이미지에서 객체를 찾는 과정 (Classification → Detection → Keypoint)
   - Pose Estimation 개념: Top-down vs Bottom-up, Heatmap vs Regression 방식, OpenPose 등 대표 모델
   - 본 체계에 사용한 **MediaPipe Hands**: 손바닥 탐지(Palm Detection) → 손 관절 21점 추정(Hand Landmark) 2단계 구조
   - 제스처 분류: 관절 좌표 기반 규칙 분류(본 체계) vs 학습 기반 분류기(후속 고도화)
   - 객체 탐지(YOLO) 계열과의 관계 (제작자 연구 연계)
   - 오인식을 줄이는 기법: 유지 시간 필터, 신뢰도 임계값, Fail-safe 설계
2. **드론 기본 지식:** 멀티콥터 비행 원리(추력, 롤·피치·요), 비행 모드, 배터리 관리, 비행 전 점검
3. **드론 관련 규정 링크** (구현 시 링크 유효성 재확인)
   - 국가법령정보센터: 항공안전법 — https://www.law.go.kr/법령/항공안전법
   - 국가법령정보센터: 드론 활용의 촉진 및 기반조성에 관한 법률 — https://www.law.go.kr/법령/드론활용의촉진및기반조성에관한법률

## 4. 수신호(제스처) 정의

### 4.1 인식 원리
MediaPipe Hands가 손 관절 21개의 좌표를 실시간으로 추정하고, 손가락의 펴짐·접힘 상태와 방향 벡터를 계산해 **규칙 기반**으로 제스처를 판정한다. 별도의 학습 데이터 수집이 필요 없다.

### 4.2 제스처 7종

| # | 명령 | 손 모양 | 판정 기준 | 유지 시간 | 드론 반응 |
|---|---|---|---|---|---|
| G1 | 전원 켜기 | OK | 엄지와 검지 끝이 맞닿고 중지·약지·소지가 펴짐 | 1.0초 | 프로펠러 회전, 이륙 대기 |
| G2 | 상승 | 엄지척 | 주먹 상태에서 엄지만 위로 (수직 ±45° 이내) | 0.5초 | 유지하는 동안 상승 |
| G3 | 하강 | 엄지 아래 | 주먹 상태에서 엄지만 아래로 (수직 ±45° 이내) | 0.5초 | 유지하는 동안 하강, 지면에서 정지 |
| G4 | 좌측 이동 | 검지로 왼쪽 | 검지만 펴고 **조종자 기준** 왼쪽 수평 방향 | 0.5초 | 왼쪽으로 이동 |
| G5 | 우측 이동 | 검지로 오른쪽 | 검지만 펴고 **조종자 기준** 오른쪽 수평 방향 | 0.5초 | 오른쪽으로 이동 |
| G6 | 전원 끄기 | 손바닥 아래로 | 다섯 손가락을 펴고 손등이 카메라를 향한 채 손이 수평 | 1.0초 | 지상: 전원 차단 / **공중: 자동 착륙 후 전원 차단** |
| G7 | 정지(호버링) | 손을 화면 밖으로 | 손 미검출 또는 신뢰도 미달 | 즉시 | 현재 위치에 정지 |

**좌우 처리:** 카메라 영상을 거울 반전해 표시하고 조종자 시점으로 판정한다. 원래 카메라 영상에서는 왼쪽 지시가 오른쪽 방향으로 찍히지만(요구사항 원문), 이 변환은 시스템이 자동으로 처리한다.

### 4.3 공통 규칙
- **Fail-safe:** 판정이 애매하면 항상 G7(호버링)로 처리한다.
- **전원 게이트:** 전원이 꺼져 있으면 G1 외의 제스처는 모두 무시한다.
- **단일 손:** 두 손이 보이면 먼저 잡힌 손만 따른다.
- **신뢰도 임계값:** 기본 0.7. 환경설정에서 조정할 수 있다.
- **권장 자세:** 카메라에서 50cm~1m 거리, 손은 가슴 높이, 밝은 조명.

### 4.4 혼동 위험과 대응

| 혼동 조합 | 원인 | 대응 |
|---|---|---|
| G2/G3 ↔ G4/G5 | 엄지척을 옆으로 눕히면 가리키는 동작처럼 보임 | 엄지 각도 ±45° 제한, 검지 펴짐 여부로 구분 |
| G3 ↔ G6 | 손을 펴다 만 상태 | G6는 다섯 손가락이 모두 펴져야 판정 |
| G6 자체 | 정면 카메라로는 손바닥 방향 판별이 가장 어려움 | 손등 방향(관절 법선 벡터)과 수평 여부로 판정, 1초 유지. 시연에서 불안정하면 대체안(주먹 1.5초)으로 전환 (8장 결정 포인트) |

### 5.1 미션 구성

- 80점 이상 "합격"으로 표시

### 5.3 실수(잘못된 습관) 유형

| E2 | 유지 시간 미달 | 제스처가 유지 시간을 채우지 못하고 끊김 (3회 이상 반복 시 기록) |

## 6. 데이터

### 6.1 저장 방식
- **공유 저장소:** Supabase(PostgreSQL) `mc_attempts` 테이블에 저장해, 교관이 같은 링크에서 모든 훈련자의 기록을 조회한다. RLS로 추가·조회만 허용하고 수정·삭제는 관리자만 한다.
- **미설정 시 대체:** Supabase 키가 없거나 연결에 실패하면 브라우저(localStorage)에 저장하고, CSV 내보내기·가져오기로 교관에게 제출한다.
- **로그인 없음:** 훈련 시작 시 계급과 이름(또는 훈련 번호)만 입력한다.
- **개인정보 최소화:** 군번, 소속 상세, 얼굴 영상은 저장하지 않는다. **카메라 영상은 기기 안에서만 처리하고 전송·저장하지 않는다.**

### 6.2 데이터 구조

| 컬렉션 | 주요 필드 |
|---|---|
| trainees | id, 계급, 이름(또는 훈련 번호), 최초 등록일 |
| sessions | id, trainee_id, 시작·종료 시각, 모드(자유/미션), 기기 유형(PC/모바일) |
| attempts | id, session_id, 미션 코드, 성공 여부, 점수, 소요 시간, 실수 코드별 횟수 |
| events | attempt_id, 시각, 확정 제스처, 기대 제스처, 신뢰도, 드론 상태(고도·위치·전원) |

### 6.3 내보내기
교관 화면에서 attempts와 실수 요약을 CSV로 내려받는다.
